# 성신당 유료 선택 → 결제 → 열람

기존 코드 확인: `D:/developer/sajudang_git/apps/web/app/pay/page.tsx`.
현재 상품 카드와 결제 버튼 사이에 다른 상품·해석자 탐색이 들어가 결제 버튼이 첫 화면에서 밀린다. 기존 주문 생성, openCheckout, payConfirm 및 열람 권한 확인을 유지하고 결제 영역의 위치를 바꾼다.

## 화면 순서
1. 해석 제목과 짧은 안내.
2. 선택 상품: 인물, 서버 확정 금액, 구매 범위, 일회성/정기결제 여부.
3. 카드 안에 `12,900원 결제하고 해석 보기` 버튼. 상품 클릭은 선택만 하고, 이 버튼 클릭으로 결제창을 연다.
4. 환불 조건 링크와 필요한 추가 입력 안내를 버튼 가까이에 배치.
5. 본문 미리보기·전체 열람 범위·다른 상품·다른 해석자는 아래 접기 영역.
6. 모바일 하단에 선택 금액과 동일 결제 버튼을 고정. 기존 떠 있는 `20자리 보기`는 결제 화면에서 숨기거나 본문 아래로 이동해 겹침을 막는다.

## 상태와 동작
- 주문 준비 중: 금액·조건을 확인 중이라는 상태와 비활성 버튼. 이전 상품 주문으로 결제할 수 없어야 한다.
- 준비 완료: 서버 주문의 금액과 선택 상품이 일치할 때 버튼 활성화. 두 버튼은 동일 실행 함수와 중복 실행 방지를 공유한다.
- 결제창 진입: 기존 openCheckout 호출. 정기결제 상품은 기존 registerCard 사용, 버튼에 금액과 결제 주기를 명시한다.
- 취소/실패: 선택과 입력 유지, 카드 옆에 짧은 안내와 재시도. 구매 내역 확인 경로 유지.
- 승인 확인: 클라이언트 복귀 URL만으로 해석을 열지 않는다. 기존 payConfirm의 서버 승인과 열람 권한 반영을 확인한다.
- 성공: 실제 구매한 인물과 항목으로 이동해 읽으려던 위치를 복원. 재방문 시 권한 확인 후 `구매한 해석 이어 읽기` 표시.
- 지연: 같은 주문 승인 재확인과 결제 내역 버튼 제공. 새 주문으로 결제를 반복시키지 않는다.
- 결제 서비스 미연결/필수 정보 없음: 기존 안내와 입력 복귀 경로 유지. 결제 가능하다고 표시하지 않는다.

## 구현 위치
- page.tsx의 product/selectTier: 선택 메시지를 결제 행동으로 연결하고 선택된 카드 바로 뒤에 구매 요약과 버튼 렌더링. 버튼 안에 버튼을 넣지 않는다.
- conversion-checkout: 주문별 조건과 결제 실행을 재사용 가능한 컴포넌트/핸들러로 분리해 상단 카드와 모바일 하단에서 공유.
- 다른 상품 및 다른 해석자 details: 결제 영역 다음으로 이동.
- 기존 결제 승인 effect와 서버 권한 검증은 유지.

`index.html`은 클릭 가능한 시안이다. 성공/취소는 시뮬레이션이며 실제 결제 및 서비스 소스 변경·배포는 하지 않았다.
