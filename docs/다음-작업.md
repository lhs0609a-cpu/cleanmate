### 0-1. 다른 드라이브로 옮기기 — `src/relocate.ts`

`Outcome`에 `MOVE`를 추가하고 U7 질문에 "다른 드라이브로 옮길래요"를 되살렸다.

옮기기는 **지우기보다 위험할 수 있다**. 지우면 격리함에 남지만, 옮기면 파일은 멀쩡한데
그 파일을 가리키던 것들이 깨진다. 그래서 대상을 삭제보다 좁게 잡았다 —
프로그램 설치 폴더·`AppData\Roaming`(앱 설정)·동기화 폴더·`node_modules`는 제외.

- 드라이브 내 상대경로를 유지해 옮긴다(`Videos\a.mp4` 와 `Downloads\a.mp4` 충돌 방지)
- 대상 드라이브에 5GB 여유를 남긴다 — 꽉 채우면 그 드라이브가 다음 문제가 된다
- 장부(`moved.jsonl`)를 **옮긴 자리에** 둔다. 외장하드를 다른 PC에 꽂아도 출처를 안다
- TOCTOU 재검증, 덮어쓰기 금지, 부분 성공 보고 — 격리와 같은 규칙
- 테스트 14개

### 0-2. 오래 안 쓴 프로그램 — `src/probes/programs.ts`

파일이 아니라 **레지스트리**를 본다. hiberfil처럼 별도 프로브다.
(U8 미지수를 만들지 않은 이유: 프로그램은 파일 스캔의 산물이 아니다.)

**실측하다 잡은 오탐이 설계를 바꿨다.** 처음엔 설치 폴더의 수정 시각을 "마지막 사용"으로
썼는데, Git이 "12개월째 미사용"으로 잡혔다 — 매일 쓰는 도구인데.
**프로그램을 실행해도 설치 폴더는 안 바뀐다.** 그 시각은 마지막 *설치·업데이트*다.

→ `UserAssist`(HKCU, 관리자 권한 불필요)의 실제 실행 기록으로 바꿨다.
Prefetch가 더 정확하지만 관리자 권한이 필요해서 못 쓴다(앱은 최소 권한 설치).

- **양성 신호가 있을 때만 제안한다.** 실행 기록이 없으면 "안 쓴다"가 아니라 "모른다" →
  제외. 터미널로만 쓰는 CLI 도구는 UserAssist에 안 남는다
- 백신·런타임·드라이버·윈도우 구성요소는 보호 목록으로 제외
- 제거는 **정식 언인스톨러(`UninstallString`) 호출**. 파일을 지우는 경로가 코드에 없다
- 되돌릴 수 없으므로 일괄 제거 API를 만들지 않았다 — UI가 하나씩 확인받는다
- 레지스트리 크기 값이 없으면 실제 폴더를 재서 채운다(0MB로 보이면 쓸모없어 보인다)
- 테스트 23개

> 파싱 버그도 하나 잡았다: UserAssist의 값 '이름'이 경로라 공백이 들어가는데
> `\S+`로 잡고 있어 "Adobe Photoshop 2026.lnk" 같은 항목을 통째로 놓쳤다.
> 고친 뒤 실행 기록 54 → 105개, 매칭 15 → 25/88로 늘었다.

## 1. 코드 서명 인증서 확보 ⚠️ 내가 못 하는 부분

파이프라인은 다 깔았다. **인증서만 없다** — 이건 구매·본인확인이 필요해서 코드로 해결되지 않는다.

- [ ] OV 또는 EV 코드서명 인증서 구매 (예: DigiCert, Sectigo. EV는 SmartScreen 평판을 즉시 얻고
      OV는 다운로드가 쌓이면서 얻는다)
- [ ] `.pfx`를 base64로 인코딩
      → `certutil -encode cert.pfx cert.txt` 후 `-----BEGIN/END-----` 줄 제거
- [ ] GitHub → Settings → Secrets and variables → Actions 에 등록
      - `CODESIGN_PFX_BASE64`
      - `CODESIGN_PFX_PASSWORD`
- [ ] 태그 하나 밀어서 서명된 설치파일이 나오는지 확인

시크릿을 넣는 순간 `release.yml`의 서명 3단계(인증서 준비 → 앱 바이너리 서명 → 설치파일 서명)가
자동으로 켜진다. 지금은 시크릿이 없어 조용히 건너뛴다 — 빌드는 정상이다.

서명이 붙으면 `web/index.html` 맨 아래 "알 수 없는 게시자" 안내 문단(`.fineprint`)을 지워야 한다.

## 3. 배포 검증 (다음 릴리스에서)

무결성 검증은 코드·CI·테스트까지 다 들어갔지만, **실제 업데이트 왕복은 아직 안 돌려봤다.**
다음 태그를 밀 때 확인할 것:

- [ ] 릴리스 자산에 `latest.json`이 올라가고 `signature`가 64자 16진수인지
- [ ] v0.4.0을 설치한 상태에서 앱을 켰을 때 업데이트가 잡히고, 검증을 통과해 설치되는지
- [ ] `signature`를 일부러 틀리게 만든 릴리스로 **거절되는지** (설치 안 되고 임시 파일 삭제)

기존 v0.4.0 릴리스의 `latest.json`은 `signature`가 빈 문자열이다. fail closed라서
**v0.4.0 → 다음 버전 업데이트는 거절된다.** 다음 릴리스부터 정상 작동하며, v0.4.0 사용자는
한 번은 수동으로 받아야 한다. (사용자 수가 적은 지금이 이 정책을 바꿀 마지막 시점이었다.)

- **랜딩 카피 축 전환** — "지킨 양" → "뭘 지우는지 알고 지웁니다". 지울 목록이 주인공,
  잠근 41.8GB는 그 아래 근거 층으로. 히어로 lede·스탯 밴드·`#why`·비교표·`meta`/`og` 전부 정합화.
  숫자도 실측과 맞췄다(2.1+8.4+4.1 = 14.6GB).
- **`og:image` + 파비콘** — `scripts/make-brand.mjs`가 1200×630 OG 이미지와 파비콘 2종을
  의존성 0으로 생성(SDF 도형 + 획 폰트). `web/public/`에 두어 vite가 그대로 배포한다.
- **접근성** — 건너뛰기 링크, `aria-hidden`(장식 아이콘·SVG), 목업에 `role="img"` + 설명,
  표에 `caption`·`scope`, `prefers-reduced-motion` 대응(CSS + JS 양쪽), `:focus-visible` 링,
  버전 표시에 `aria-live`.
- **macOS 정직한 CTA** — Windows 빌드밖에 없으므로 가짜 다운로드 버튼을 만들지 않았다.
  macOS 방문자면 버튼을 "브라우저에서 체험하기"로 바꾸고 준비 중임을 밝히고,
  Windows 설치파일 링크는 따로 남긴다.
- **자동 업데이트 무결성 검증** — CI가 SHA-256을 `latest.json`에 박고(서명 뒤에 계산),
  앱이 대조하고, Rust가 실행 직전에 다시 대조하고 불일치면 지운다. fail closed.
  `verifyIntegrity` 순수 함수 + 테스트 7개. `download_update`는 https만 받는다.
- **코드 서명 파이프라인** — 시크릿이 있을 때만 도는 3단계. 앱 바이너리와 설치파일 모두 서명.
  `cleanmate.iss`의 오해 부르는 `SignTool=` 주석 제거(CI가 하는 일이다).
- **`updater/latest.json` 이원화 정리** — 앱은 릴리스 자산만 읽는다는 사실을 파일 안에 명시하고
  더미 서명으로 형식만 보여주는 예시로 남겼다.
- **CI에 테스트 추가** — `npm test`가 릴리스 빌드 앞단에 들어갔다. 엔진이 깨진 채로 배포되지 않는다.
