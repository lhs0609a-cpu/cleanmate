# 관리자 화면·상담 폼 — 켜는 법

> 이 문서 하나만 따라 하면 상담 폼과 `/admin.html`이 동작한다.
> 아무것도 안 해도 **랜딩과 앱은 그대로 돈다** — 폼과 관리자 화면만 조용히
> "지금은 접수가 되지 않습니다"라고 답한다(그게 거짓말을 안 하는 방식이다).

---

## 0. 무엇이 생겼나

```
api/
  _lib/store.js        Upstash Redis를 REST로만 쓴다 (의존성 0)
  _lib/auth.js         관리자 세션 — 서명된 쿠키 하나
  _lib/http.js         응답·본문 읽기·요청자 식별·앱 출처 허용(CORS)
  _lib/github.js       릴리스 다운로드 수 (10분 캐시)
  inquiry.js           POST  상담·제휴 문의 접수
  ping.js              POST  익명 설치 신호 (앱이 하루 한 번)
  public-stats.js      GET   랜딩이 쓰는 다운로드 수
  admin/session.js     GET/POST/DELETE  로그인
  admin/inquiries.js   GET/PATCH        문의 목록·상태·메모
  admin/stats.js       GET              대시보드 숫자 전부
web/admin.html         관리자 화면
web/src/admin.ts       그 화면의 코드
```

의존성은 **하나도 안 늘었다.** Upstash는 SDK 없이 `fetch`로 부른다 —
엔진이 외부 의존성 0인 원칙(`docs/배포-아키텍처.md` §0)을 서버에서도 지킨다.

## 1. 저장소 붙이기 (2분)

1. Vercel → 이 프로젝트 → **Storage** 탭 → **Create Database** → **Upstash Redis**
2. 지역은 프로젝트와 가까운 곳(서울이 있으면 서울).
3. **Connect Project** 를 누른다.

이러면 환경변수 두 개가 **자동으로** 들어간다:

```
UPSTASH_REDIS_REST_URL
UPSTASH_REDIS_REST_TOKEN
```

무료 한도는 하루 요청 1만 건이다. 방문자가 하루 수천 명이 돼도 남는다
(랜딩의 다운로드 수는 10분 캐시라 Redis를 거의 안 건드린다).

---

## 2. 관리자 비밀번호 정하기 (1분)

Vercel → **Settings → Environment Variables** 에 두 개를 넣는다.
Production·Preview·Development 전부 체크.

| 이름 | 값 | 왜 |
|---|---|---|
| `ADMIN_PASSWORD` | 길고 아무렇게나 (20자 이상) | 이거 하나가 관리자 화면의 전부다 |
| `ADMIN_SESSION_SECRET` | 또 다른 임의 문자열 32자 이상 | 쿠키 서명 키. 없으면 비밀번호에서 파생하지만, 그러면 비밀번호를 바꿀 때마다 세션이 전부 끊긴다 |

값 만들기:

```bash
node -e "console.log(require('node:crypto').randomBytes(24).toString('base64url'))"
```

> `ADMIN_PASSWORD`가 없으면 로그인 자체가 막힌다(503).
> 빈 문자열로 통과되는 일은 없게 해뒀다 — 그게 제일 흔한 사고다.

### 선택: `GITHUB_TOKEN`

안 넣어도 된다. 넣으면 GitHub API 한도가 시간당 60회 → 5,000회가 된다.
읽기 전용 토큰이면 충분하다(`public_repo`도 필요 없다 — 공개 저장소다).

## 4. 앱의 익명 신호

데스크톱 앱이 하루에 한 번 `POST /api/ping` 을 보낸다.

**보내는 것 (셋뿐):**

| 값 | 예 | 왜 |
|---|---|---|
| `installId` | 임의의 UUID | 같은 기기를 두 번 세지 않으려고 |
| `version` | `0.23.0` | 업데이트가 도달하고 있나 |
| `os` | `windows` | 맥 빌드가 얼마나 급한가 |

**안 보내는 것:** 파일 이름·경로·용량, 스캔 결과, 사용자 이름, 고른 폴더,
IP(요청 제한에만 쓰고 저장하지 않는다). 브라우저 데모(`/app.html`)는
**아예 안 보낸다** — 눌러본 사람을 사용자로 세면 우리가 우리를 속인다.

서버에는 **개수만** 남는다. `PFADD`(HyperLogLog)를 쓰기 때문에 설치 ID
목록이 우리 손에 남지 않는다 — 세는 데는 충분하고, 안 남기는 편이 낫다.

앱 도움말의 **"이 앱이 밖으로 보내는 게 있나요"** 에 이 내용이 그대로 적혀
있고, 그 옆에 끄는 버튼이 있다. 끄면 그날부터 아무것도 안 나간다.

### 이 신호만 교차 출처를 연다

앱 화면의 출처는 `http://tauri.localhost`이고 신호는 `cleanmate-henna.vercel.app`
으로 간다 — 브라우저(WebView2)에겐 교차 출처다. 그래서 `/api/ping`만
`Access-Control-Allow-Origin`을 돌려준다. **없으면 신호는 한 건도 안 들어온다.**
프리플라이트(OPTIONS)에서 막히고, 앱은 실패를 조용히 삼키므로(그래야 통계
때문에 사용자 화면에 오류가 뜨지 않는다) 아무도 모른 채 '설치된 기기'만
영원히 0에 머문다. `src/web-contract.test.ts`가 핸들러를 실제로 불러 이걸 잡는다.

허용 목록은 앱이 쓰는 출처뿐이다(`api/_lib/http.js`의 `APP_ORIGINS`).
`*`로 열지 않는다 — 아무 웹페이지나 부를 수 있으면 대시보드의 '실측'이 거짓이 된다.
문의·관리자 API는 우리 도메인에서만 부르므로 이 문이 없다.

> 도메인을 바꾸면 `web/src/app.ts`의 `PING_URL`도 같이 바꿔야 한다.
> 이미 설치된 앱은 옛 주소로 계속 보낸다 — 옛 도메인을 살려두거나 그 기기들을
> 못 세는 것 중 하나다. 지어낸 숫자로 메우지 않는다.

> ★ 랜딩과 앱은 "파일은 기기를 한 바이트도 떠나지 않습니다"를 약속한다.
> 그 약속은 **파일**에 대한 것이고 이 신호엔 파일이 한 조각도 없다.
> 그래도 화면에 먼저 밝히고 끄는 버튼을 옆에 둔 이유는, 숨기고 보내는 순간
> 저 문장 전체가 못 믿을 말이 되기 때문이다.

## 5. 대시보드가 말하는 것과 말하지 않는 것

| 칸 | 출처 | 믿을 수 있나 |
|---|---|---|
| 내려받은 횟수 | GitHub 릴리스 `download_count` | 실측 (봇 다운로드가 섞일 수 있다) |
| 설치된 기기 | 익명 신호의 고유 수 | 실측 (통계를 끈 기기는 빠진다) |
| 오늘/이번 달 켠 기기 | 같은 신호, 날짜별 고유 수 | 실측 |
| 들어온 문의 | 상담 폼 | 실측 |
| **받고 설치 안 한 사람** | — | **못 잰다.** 설치를 안 하면 신호가 없다 |

마지막 칸을 추정치로 채우지 않는다. 채우는 순간 대시보드 전체가 추측이 되고,
추측을 보고 내린 결정은 되돌리기 어렵다.

"내려받기 ÷ 설치"를 전환율처럼 읽지 마세요. 세는 곳이 달라서 그 나눗셈은
의미가 없다. **추세**로 본다 — 내려받기가 느는데 설치가 안 늘면 설치 단계에서
막히는 것이고, 그건 대개 "Windows의 PC 보호" 경고다.

## 6. 스팸은 어떻게 막나 (캡차 없이)

캡차는 봇보다 사람을 더 많이 막는다 — 특히 이 폼을 쓸 사람들을.
대신 셋을 쓴다. 셋 다 걸려도 화면엔 **성공했다고 답한다** (봇에게 막혔다고
알려주면 우회를 시도한다).

1. **허니팟** — 사람 눈에 안 보이는 칸(`#inq-website`)이 채워져 있으면 봇이다.
2. **제출 속도** — 폼이 뜬 지 3초 안에 보내는 건 사람이 아니다.
3. **횟수 제한** — 같은 IP에서 10분에 5건까지. 로그인 시도는 10분에 8번까지.

## 7. 로컬에서 돌려보기

`vercel dev`가 있으면 서버 함수까지 함께 돈다:

```bash
npx vercel dev
```

`npm run dev`(Vite)만 켜면 화면은 뜨지만 `/api/*`가 없다.
그때도 **아무것도 안 깨진다** — 폼은 "지금은 접수가 되지 않습니다"라고 답하고,
랜딩의 다운로드 수 칸은 통째로 사라지며, 관리자 화면은 로그인 화면에 머문다.

## 8. 서버 함수는 무엇으로 잠겨 있나

`npm test`가 이 세 파일에서 **핸들러를 실제로 불러** 응답을 본다. Redis도
네트워크도 필요 없다 — store.js는 `fetch` 하나로만 Upstash를 부르므로
테스트가 그 `fetch`를 바꿔 끼우고 **어떤 명령이 나가는지**를 그대로 본다.

| 파일 | 잠그는 것 |
|---|---|
| `src/api-auth.test.ts` | 지어낸·고친·지난 토큰으로는 관리자 API가 401만 준다. 맞는 비밀번호로 받은 쿠키는 실제로 문을 연다. 비밀번호가 없으면 빈 문자열로도 못 들어온다 |
| `src/api-inquiry.test.ts` | 접수했다고 답했으면 실제로 저장까지 갔다. 저장이 깨지면 503으로 정직하게 답한다. 레코드에 IP가 안 섞인다. 봇은 조용히 통과시키고 안 남긴다 |
| `src/api-ping.test.ts` | 설치 ID가 집합·목록에 값으로 안 들어간다(§4의 약속). `seen:` 키에 만료가 붙어 있다. 파일 관련 값을 보내도 저장 명령에 안 실린다 |

> ★ 왜 소스를 읽는 테스트로는 부족했나
> 전에는 "`requireAdmin(`이 소스에 적혀 있는가"를 봤다. 그건 **문이 달려
> 있는지**를 보는 것이지 **문이 잠기는지**를 보는 것이 아니다. 실제로 불러
> 보고 나서야 셋이 나왔다 — 전부 그 방식으로는 영원히 안 보였다.
>
> - `Cookie: tc_admin=%` 한 줄이면 관리자 API가 401이 아니라 **500**이었다.
>   `decodeURIComponent('%')`가 던지는 예외가 `requireAdmin` 밖으로 그대로
>   튀어나갔다. 관리자 화면은 왜 안 되는지 모른 채 흰 화면이 된다.
> - 서명 길이를 '글자 수'로 재고 비교는 '바이트'로 했다. 한글 43자를 서명
>   자리에 넣으면 `timingSafeEqual`이 길이 불일치로 던졌다 — 같은 500.
> - 본문을 못 읽으면 `readJson`의 내부 오류(영어)가 413과 함께 폼 밑에
>   그대로 떴다. 이제 길이 초과만 413이고, 나머지는 400 + 한국어다.
